## UX와 접근성 QA

새 화면이므로 구현자와 다른 에이전트가 개발 환경에서 3회 검수한다. 회차마다 시작 전에 계획(후보 SHA, 항목, 기대 결과, 환경, 격리 저장 경로, 증거)을 적고 기능과 UX를 모두 본다.

| 회차 | 집중 | 페르소나 |
|---|---|---|
| 1 | 인수조건, 입력과 상태와 결과, 처음 보는 사람의 규칙 이해 | 요구사항 검수자, 처음 사용자 |
| 2 | 오류·취소·복구, 탐색, 작은 화면, 큰 글자, 영어 긴 이름, 색에 기대지 않는 구분 | 사용자 관점 검수자 |
| 3 | 기능 사이 연결, 재시작과 저장 복구, 반복 플레이의 자연스러움 | 회귀 검수자, 반복 사용자 |

필수 재료 게이트(`ui_gate.py`)를 먼저 통과하고, 기준 그림과 실행 화면의 차이를 기록해 고친다. 3회 뒤에도 미해결이 남으면 사용자에게 추가 회차를 품의한다.

## 출시 포지셔닝과 획득

- 한 문장: 범주가 숨어 있는 카드 묶기 퍼즐. 플레이 중에는 광고가 없다.
- 첫 스크린샷과 설명 첫 줄에서 "네 장의 공통점을 찾아라"와 "숨은 카드를 열어라"를 보여 준다. 정렬식 연상 솔리테어와의 차이를 그림으로 드러낸다.
- 제목 후보: `Four Alike: Hidden Category Cards`(영어), `끼리끼리: 연상 카드 퍼즐`(한국어). 등록 전에 30자 제한과 상표를 다시 확인한다.
- 유입은 마켓 검색과 일일 도전 결과 공유에 기댄다. 유료 광고는 하지 않는다.
- 웹 검색 유입 페이지는 출시 뒤 별도 설계로 진행한다.

## 소프트론칭

별도의 제한 국가 소프트론칭은 하지 않고(사용자 결정: 공개 출시까지) 내부 테스트 트랙을 거쳐 바로 공개한다. 대신 공개 뒤 첫 2주를 관찰 기간으로 두고 아래를 본다.

| 지표 | 보는 값 | 조치 기준 |
|---|---|---|
| D1 잔존 | 20% 이상 | 미달이면 첫 5판과 튜토리얼 수정 |
| 스테이지 10 도달 | 설치의 40% 이상 | 미달이면 T2 구간 난도 완화 |
| 등급별 클리어율 | 목표와 10%p 이내 | 벗어나면 관대함 범위 조정 |
| 보상형 수락률 | 칸이 가득 찬 판의 15% 이상 | 5% 미만이면 부스터 구성 재검토 |
| 광고 불만 리뷰 | 글 리뷰의 20% 이하 | 40% 초과면 전면 간격과 시작 조건 조정 |
| 평점 | 4.0 이상 | 미달이면 전면 광고를 원격 설정으로 끈다 |

## 롤백과 운영

| 상황 | 대응 |
|---|---|
| 전면 광고로 인한 평점·잔존 하락 | 원격 설정 `interstitial_level_end_enabled`를 끈다. 빌드가 필요 없다 |
| 광고 SDK 문제 | 배치별 끄기 스위치로 해당 배치를 끈다 |
| 범주나 판의 오류 | 원본 표에서 내리고 팩을 다시 만들어 새 버전을 낸다. 급하면 해당 범주가 든 일일 도전 날짜를 다음 버전에서 대체한다 |
| 치명적 오류 | Play Console에서 출시를 중단하고 직전 정상 버전을 다시 올린다. 저장 형식은 낮은 버전으로 되돌릴 수 없으므로 저장 버전을 올린 릴리스는 되돌리지 않고 수정 버전을 낸다 |
| 심사 거절 | 사유를 확인해 범위 안(문구, 그림, 신고 내용)이면 고쳐 다시 제출하고, 제품 동작 변경이 필요하면 사용자에게 보고한다 |

운영 기록은 `release/` 아래에 출시별 상태와 근거 위치를 남긴다. 검수 원본(전체 해상도 캡처, 로그)은 NAS에 보관하고 저장소에는 요약과 위치만 둔다.
